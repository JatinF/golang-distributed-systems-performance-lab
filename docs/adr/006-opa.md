# ADR 006: OPA is not on this hot path

## Status

Accepted.

## Context

A policy engine belongs with the control plane that activates bundles and proves authorization decisions. That work is a different repository. Putting OPA in front of every hashed job would measure policy latency in a performance lab that is here to measure the pool, RPC, cache, broker, and database.

## Decision

This process does not load an OPA bundle and does not call OPA. Admission uses the in-memory Ed25519 token check in ADR 007, then the ledger and the pool.

If that verifier cannot run, the call is rejected. There is no fallback allow. Policy activation failure in the runbook means this fail-closed behavior. It does not mean an OPA bundle was pushed.

## Consequences

Authorization tests cover expired tokens, bad signatures, the wrong audience, a missing bearer, and another tenant. They do not cover OPA partial evaluation. A reader who wants bundle activation should look at the control-plane repository, not at these timings.
